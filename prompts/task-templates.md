# 精简任务提示词

按任务填写目标、范围和完成条件；未知且可通过源码查明的信息可直接写“请从现有实现确认”。这些模板不改变全局 AGENTS.md、项目指令或当前角色权限。

## 开发或修复

```text
目标：[具体问题与预期行为；有条件时附一个输入/输出例子]。
范围：[仓库或目录、相关模块]。保留：[兼容性、现有行为、已有改动]。
线索：[报错、日志、复现入口或相关文件；只写已知事实]。
完成条件：[可观察的结果与适用验证；需要运行或检查界面时明确写出]。
请完成实现、适用验证和发现问题的修复，再交付结果。常规选择按现有约定推进；关键决定缺失时说明所需信息，同时继续独立工作。
```

## 只读代码或方案审查

```text
只读审查 [具体变更、方案或证据] 是否满足 [需求和验收边界]。
检查错误前提、遗漏、回归与兼容性问题。每项阻塞问题给出位置、依据、实际后果和所需修正；区分事实、推测和未验证项。
结论覆盖所请求的范围，并说明证据不足处。
```

## 机器人问题

```text
目标：[手套重定向 / IK / 增益问题与具体症状]。
范围与线索：[checkout、设备/模型、输入或日志位置；未知项从现有资料核实]。
保留：[现有控制接口、校准语义、限幅、停止/保持行为]。
完成条件：[同输入回放或明确授权的验证，以及需要达到的指标]。
本次操作权限：[如“仅源码与离线回放”或具体获准的硬件操作]。
请定位并修复范围内的问题，报告源码、静态检查、回放、运行、硬件/HIL各自实际获得的证据。
```

## Herdr Planner 任务

将“开发或修复”模板中的目标、范围、线索和完成条件发给已验证的同队 Planner。当前角色协议已有身份路由、关联字段、Coder 写入边界、Reviewer 只读和四轮上限，无需在每条任务中复制整套协议。任务涉及特殊权限或例外时，明确写出其范围。

## 论文审读

```text
严格审读 [论文文件或链接]，重点判断 [我关心的问题]。
按全局 AGENTS.md 的四问回答，并为关键判断标注论文位置：实际问题、声称贡献、reviewer 最可能攻击的点、同方向工程师的精读/跳读建议。
区分论文主张、实验直接支持的事实和你的推断。
```

## 使用原则

- 写清完成条件，避免“先做一版等我确认”意外截断已授权的完整任务。
- 只列相关资料；无需要求每次改动都读完整架构、部署和数据库文档。
- 保留真正需要用户决定的兼容性、权限与安全边界；已经明确的决定不重复询问。
- 验证覆盖实际风险和项目要求；通过后不因回复新消息就重复运行同一套检查。
